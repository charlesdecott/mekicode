Comment fait-on cohabiter le chat et le canvas ?

Le chat actuel = NiceGUI (UI pilotée en Python). Le canvas mekistudio = FastAPI + Jinja + Alpine.js + JS pur (cables.js, collision.js, canvas.js…). Les deux partagent le même back (mekicore + mekihub). Question : quelle stratégie d'intégration ?

A

Canvas embarqué DANS NiceGUI ★ recommandé

Un seul serveur (NiceGUI tourne déjà sur FastAPI/uvicorn). Le canvas mekistudio est servi comme bundle statique + une route WebSocket FastAPI montée sur l'app NiceGUI. Onglet « Chat » = page NiceGUI ; onglet « Canvas » = la page canvas. Les deux lisent mekihub.subscribe().

┌──────────── 1 serveur (NiceGUI/FastAPI, 1 port) ───────────┐ │ Tab CHAT (NiceGUI) Tab CANVAS (Alpine+JS pur) │ │ │ │ │ │ └──────── mekihub events ────┘ (WS bridge) │ │ │ │ │ mekicore run_agent + nos hooks │ └────────────────────────────────────────────────────────────┘
  • garde tout mekichat/mekihub/Discord, 1 port, réutilise le JS canvas quasi tel quel
  • à faire la « colle » : route WS qui traduit events mekihub → impulsions canvas + REST node CRUD
B

Tout reconstruire sur la stack mekistudio

On abandonne NiceGUI. On reprend le front mekistudio en entier (Jinja + Alpine + WS) et on réécrit le chat dans ce style, en branchant mekicore/mekihub à la place du Claude SDK. Canvas, multi-canvas, éditeur, terminal « gratuits ».

┌──── 1 serveur (FastAPI + Jinja + Alpine, stack unique) ─────┐ │ Tab CHAT (réécrit Alpine) Tab CANVAS (mekistudio natif) │ │ même moteur de rendu │ └────────────────────────────────────────────────────────────┘
  • garde stack 100 % cohérente, UX mekistudio éprouvée, canvas natif
  • jette le front NiceGUI (UI chat, tool-cards, thème Phosphore) → gros réécriture
C

Deux sous-apps montées, onglets = 2 « mondes »

Coquille FastAPI qui monte (1) NiceGUI pour le monde chat et (2) les routes mekistudio pour le monde canvas, chacune dans son iframe/route. La barre d'onglets est dans la coquille. Back mekihub partagé.

┌──────────── coquille FastAPI + barre d'onglets ────────────┐ │ iframe CHAT (NiceGUI) │ iframe CANVAS (mekistudio) │ │ └──────── mekihub partagé ────────┘ │ └────────────────────────────────────────────────────────────┘
  • garde chaque monde dans sa stack native, réécriture minimale
  • coût 2 fronts à maintenir, sync inter-onglets via iframe pénible, « 2 apps » au lieu d'1

Mon conseil : A — on préserve l'énorme investissement mekichat/mekihub/Discord, un seul port, et le JS du canvas mekistudio est pur et autonome donc réutilisable presque tel quel. Le vrai travail devient la « colle » events↔impulsions, pas une réécriture.
