Découpage en sprints — où trace-t-on la ligne du Sprint 1 ?

Le tout est trop gros pour un seul plan. Voici la roadmap complète. Le Sprint 1 est ma reco de première tranche démo-able (verticale, livrable). Dis-moi si tu veux tirer des éléments des sprints suivants dans le Sprint 1, ou en sortir.

▶ Sprint 1 — Fondations + Canvas MVP

  • Refactor chat → ChatComponent NiceGUI réutilisable (extrait de mekichat)
  • HookBus dans mekicore : pre_tool/post_tool/on_event autour de dispatch_tools (nos hooks)
  • s15 — Permissions 3 tiers autour de dispatch (deny / allow / ask), « ask » async surfacé en événement
  • Coquille à onglets : Tab Chat | Tab Canvas (NiceGUI)
  • Canvas NiceGUI : pan/zoom + couche câbles SVG 45° + comètes (réutilise géométrie pure mekistudio)
  • BaseNode / BaseComponent + registry + parenting déduit
  • Nodes : KernelNode, ChatNode (=ChatComponent), QueueNode (sous le chat)
  • Impulsions branchées sur le HookBus (comète + glow par appel d'outil)

Sprint 2 — Fichiers

  • ExplorerNode (FileTreeComponent, lazy, sandboxé)
  • EditorNode + preview (CodeMirror, save atomique)
  • FolderNode (chaîne de dossiers matérialisée)
  • SubcanvasNode (cadre auto-borné)
  • Éditeurs éphémères auto-spawn quand l'agent lit un fichier (+ pin, TTL)
  • Impulsions fichier : read/write/edit → comète vers l'éditeur

Sprint 3 — Multi-user temps réel sur le canvas

  • Présence (curseurs/avatars) sur le canvas
  • File d'attente partagée visible dans la QueueNode (multi-auteurs)
  • Sync canvas multi-clients (état partagé, broadcast)
  • TerminalNode (PTY) + GitNode (statut branche)

Sprint 4 — Échelle & polish

  • Multi-canvas (plusieurs onglets canvas)
  • Worktrees git = subcanvas imbriqués
  • QCM / ask_user de l'agent en plein tour
  • Palette d'ajout de nodes, thème, perfs
